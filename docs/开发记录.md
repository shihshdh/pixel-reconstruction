# Pixel Reconstruction · 开发记录

> 这份文档是开发过程中的交接与验收记录，按时间保留，部分内容（部署 ID、API 版本、站点地址）已被后续版本取代。项目概况见根目录 [README](../README.md)。

上传一张照片，使用 Apple SHARP 生成高斯泼溅场景，在浏览器中查看、运镜、导出视频，也可以先用豆包修图再重新生成。

- 前端站点：[gausssharp.netlify.app](https://gausssharp.netlify.app)
- 本版 CPU API 配置：[ruhua-api v13](https://ruhua-api-aa5d4d3-v16.app.beam.cloud)
- 后端部署包及接口说明：[backend/beam/README.md](../backend/beam/README.md)

前端是 Next.js 静态导出，托管在 Netlify；私人场景文件通过 Netlify Edge Function 流式转发。后端使用 Beam 的 CPU 网关和独立 GPU 任务队列，结果及模型缓存保存在持久卷。旧 Modal/阿里云实现保留作历史参考，不是本版运行入口。

## 本地启动与发布

发布顺序：先打包客户端并装到本机验证，再推送 GitHub（含 Release 安装包），最后发布网站。

### 2026-09-25 客户端 1.1.1：上传读取进度、大图本地压缩、液态玻璃开场

- 上传前先把照片完整读进内存并显示进度（`lib/photo-prep.ts`）。电脑上的 iCloud 照片常是云端占位文件，Windows 取回原图期间页面以前没有任何反馈；现在 6 秒无进展会提示“始终保留在此设备上”，并可取消。读完后显影动画、助手看图和上传都用内存副本。
- 20MB 以内原图逐字节上传；超过 20MB 才在本地压缩：长边上限 4096（与服务端一致），JPEG 质量从 0.95 起逐级尝试，取第一个 ≤19.5MB 的结果。可选照片上限放宽到 50MB。浏览器解不开的超大 HEIC 会提示先导出 JPG。
- 开场改为白底、品牌蓝 logo。四个像素块由 WebGL 画成液态玻璃（`lib/intro-glass.ts`）：超椭圆倒角、按 Snell 定律折射并分通道色散、菲涅尔与随光向变化的边缘高光、Beer–Lambert 着色、柔和投影；轨迹与 CSS 时间线同一时钟，在 Worker 中经 OffscreenCanvas 渲染，不受首页场景解析影响。没有 WebGL 时保留原平面像素，减少动态效果时不启用。飞入页眉时颜色渐变到页眉文字色。
- 验证：生产 CSP 下桌面/手机开场无报错；模拟后端上传 2.57MB 原图逐字节一致、31.9MB 压到 9.33MB；模拟 iCloud 读取卡住 9 秒时提示与取消按钮正常。

### 待发布：鲸鱼娘网页与图像理解（2026-09-24）

已实现但尚未部署到 Beam/Netlify。DeepSeek 官方当前 `deepseek-flash` 支持图片输入，沿用服务端 `DEEPSEEK_API_KEY`，不启用本站 GPU。网页查看默认关闭，权限只在当前页面会话的内存中保存；开启后，仅在用户主动发送消息时读取当前活动页面文字（含滚动区域）及图片。上传中使用完整原图，工作室和修图页读取当前作品原图；不会把粒子动画冒充用户照片。输入框、隐藏页面、助手对话、标记为私密的区域不读取；页面文本中的链接与常见凭证形态会脱敏。

每次最多附 8 张页面图片，长文本截取到约 12,000 字，未能读取的图片会在上下文里注明。大量图库内容应打开具体作品再询问；WebGL 当前视角可通过“截取屏幕”提供。截图先预览，发送后才交给 DeepSeek；浏览器必须让用户选择共享范围，捕获单帧后立即停止共享。移动端不支持屏幕捕获时可上传截图。截图内的隐私文字不会自动遮挡，UI 提醒先检查。图片不进入本地聊天缓存、Beam 作品卷或日志；供应商对请求的处理按其服务政策执行。

服务端只接收内联 JPG/PNG/WebP，不接受可任意抓取的外部地址。单图 1MiB、像素上限、静态图片校验和请求体 3MB 上限在调用模型前执行，重编码移除图片元数据；文字与图片沿用聊天频率和每日额度。默认视觉模型为 `deepseek-flash`，可在后端使用 `DEEPSEEK_VISION_MODEL` 配置。先部署 CPU 网关并确认 `/healthz` 返回 `assist_vision: true`，再更新前端/文件转发网关地址并发布；旧后端下图像入口会禁用，避免假装已识图。

离线后端验证：`.venv-tests/Scripts/python.exe -m unittest discover -s backend/beam -p test_assist.py`。浏览器验证：启动构建产物的本地 HTTP 服务后运行 `node scripts/verify-companion-vision.cjs`（GPU 与 DeepSeek 调用被拦截，不产生模型费用）。

需要 Node.js 和 npm。在项目根目录双击 **启动PixelReconstruction.bat**，或执行：

```powershell
npm install
npm run dev
```

打开 [localhost:3000](http://localhost:3000)。启动脚本**只启动前端**，不会在本机启动 GPU 服务；默认访问 `.env.local` 指定的 Beam CPU API：

```dotenv
NEXT_PUBLIC_BEAM_API=https://ruhua-api-aa5d4d3-v16.app.beam.cloud
```

修改此地址后需重启开发服务；发布站点则需重新构建。`NEXT_PUBLIC_*` 会进入浏览器，只能放公开地址，不能放任何 API Key。

双击 **部署到Netlify.bat** 会先执行 `npm run build`，成功后通过 CLI 发布 `out/` 及 `netlify/edge-functions/`，覆盖已有 `gausssharp` 站点；构建失败即停止，不会自动发布旧产物。Netlify CLI 需保持账户登录。只有 `out/` 是静态发布目录，不要把整个项目上传。**当前版本需通过 CLI 同时部署 Edge Function，不能只把旧静态 ZIP 拖到 Netlify。** 更换 CPU API 后还需同步 `netlify/edge-functions/scene-file.ts` 内固定的网关地址。

批处理文件必须保存为 **CRLF 换行**。2026-09-23 修复了混用 LF/CRLF 导致 Windows 截断命令、双击部署失败的问题，并在 `.gitattributes` 固定此格式。部署入口现在分为构建、发布包检查、上线三步；缺少 npm 或任一步失败会停在窗口内显示错误。

## 手机加载优化（2026-09-19）

根据用户对画质的反馈，**手机与电脑现在默认使用同一份完整模型**。不再因屏幕宽度、省流量模式或历史轻量缓存而选择抽样场景。保留现有无损压缩传输，示例完整 `.splat` 为 37,748,736 字节，网络传输约 27,647,024 字节，解压后逐字节还原。

新生成、在线打开作品和默认保存都选择完整模型。已有轻量缓存不删除，仅在离线且没有完整缓存时显示，并明确标记“历史轻量缓存（细节有减少）”；联网可恢复完整模型。`preview=mobile` 接口仅为历史兼容保留，正常手机流程不调用它。作品库保存原图和完整模型，不自动下载 MP4；保存完成后离线重开不需要网络。

下载中先显示原图。持续有数据时不再受旧三分钟固定超时限制；连续 45 秒无进展会尝试重连，单次下载最多 3 个文件 GET、总体最多 10 分钟。当前页面内保留已收字节，续传严格校验强 ETag、MIME 和 Content-Range；服务器返回全量 200、文件版本变化或协议校验不符时丢弃旧片段，绝不拼接不同文件。压缩包损坏时可回退原始完整文件。刷新整个页面或手动“从头重新下载”不保留未完成片段。

查看器保留完整点数、32 位协方差与原有像素比例，只在上传 GPU 后释放重复的 CPU 纹理缓存。解析失败或 WebGL 上下文被系统回收会显示恢复入口；已完整下载的 Blob 可用于再次解析，不必重新取整份模型。

正式站经同源 `/scene-file/` 流式取文件，固定上游、保留签名校验、拒绝任意外部目标，响应禁止公共 CDN 缓存。它使用当前 Netlify Free 套餐的现有配额，没有升级套餐；流量与调用仍计入套餐用量，不承诺无限免费。GPU 资源、最大实例数和零保温设置不变。

本轮生成的扩图、房间模型和首页布局实验已按用户要求撤回，首页保留此前线上素材和布局。另按用户新要求添加作者联系卡，不使用本轮被否定的生成图。

## Serverless 配置与费用

| 服务 | 资源 | 缩容设置 |
| --- | --- | --- |
| GPU 推理 | RTX 4090 24GB，2 CPU，16GiB RAM | 最少 0、最多 1，保温 0 秒 |
| CPU 网关 | 0.5 CPU，1GiB RAM | 最少 0、最多 1，保温 0 秒 |

只有提交生成或重新生成会唤醒 GPU。浏览页面、查看首页场景、状态查询、下载和豆包修图都不需要 GPU 在线。没有请求时按 Beam 调度收缩至零；平台调度需要短暂时间，不能把保温 0 秒理解成任务结束的同一毫秒停止计费。持久存储与第三方服务费用另行查看账户账单。

首次权重准备的真实首跑约 **233 秒**。当前版本复用磁盘权重的一次独立任务为 **55.2 秒**，其中导入运行环境 14.1 秒、加载模型 17.9 秒、神经网络前向推理 2.2 秒、紧凑预览转换 7.5 秒。每次缩容后仍需载入模型，Beam 容器启动时间不等于可交付结果的时间；这些是单次样本，不是固定时延承诺。任务结束后已确认 GPU 容器回到 **0 个**。

按 2026-09-19 [Beam 公开价格](https://www.beam.cloud/pricing)的分项计算，GPU 容器运行期间约 **US$0.901/小时**：GPU 约 $0.69，加上 2 CPU 与 16GiB RAM；CPU 网关、存储及豆包另计。官网另有 $1.77/小时示例，与当时分项计算不一致，因此这里仅供估算，最终以实际账单为准。

以 55.2 秒样本比较每个任务的计算成本：

| 配置（均为 16GiB、零保温） | 按分项计算每小时 | 55.2 秒费用 | 要维持原单次成本，总耗时须达到 |
| --- | --- | --- | --- |
| RTX 4090 + 2 CPU，当前选择 | $0.90096 | $0.013815 | 55.20 秒 |
| RTX 4090 + 4 CPU | $0.99096 | $0.015195 | ≤50.19 秒 |
| RTX 5090 + 2 CPU | $1.30176 | $0.019960 | ≤38.20 秒 |

计算采用 RTX4090 $0.000191667/秒、RTX5090 $0.000303/秒、CPU $0.0000125/核·秒、RAM $0.0000021/GiB·秒。当前纯 GPU 前向仅约占总耗时 4%，换更贵 GPU 无法据此保证单次成本相近；5090 还需要更新当前 CUDA/PyTorch 环境。此版保持 4090 与原资源配比，优先减少重复数据处理，没有用常驻 GPU 换取表面速度。表中未计独立 CPU API、第三方修图等费用。

同日同图的再次对照：旧 GPU v2 总计 **50.3 秒**，新 GPU v3 总计 **46.1 秒**；预览转换及复制从 **7.143 秒降至 2.669 秒**，实际启用 `preview_engine=numpy`。模型的完整预测阶段分别约 40.9/41.2 秒，速度差主要来自预览处理；保留全量 1,179,648 点。按相同分项费率估计，单次生成计算费用约从 **$0.01259 降到 $0.01154（减少8.3%）**。这是少量样本，账单启动与收缩边界、负载和文件 I/O 仍有波动；没有通过提高资源配比取得结果。

应用默认每天最多 **30 次生成/重建、30 次修图**，按 UTC 日期重置；单 IP 每分钟最多 3 次上传，GPU 最多同时运行 1 个任务。生成任务最长 15 分钟，不自动重试。这些是应用保护，**不是账户硬金额上限**。要限制总支出，还需管理 Beam 与豆包账户预算。

## 作品保存、修图与访问权限

作品库把原图、PLY、紧凑预览和下载成功的视频等文件保存在当前浏览器的 IndexedDB，并请求持久存储。浏览器可能拒绝持久化请求，也可能因清理站点数据、隐私模式、空间不足或卸载而删除数据；需要长期保留的作品请另行下载。手动删除作品会删除本地记录与缓存，不会自动删除 Beam 持久卷上的文件。

新版浏览器预览优先使用全量点 `.splat`，样本从约 66.1MB PLY 缩为 37.7MB，减少约 **43%**；原始 PLY 仍可单独下载，但下载和写入本地作品库需要时间，不保证即时完成。已有作品可以在鉴权后由 CPU 补建预览，不额外启动 GPU；具体耗时仍取决于网络和浏览器。

在此基础上，支持的浏览器使用**无损压缩传输**：真实 37.75MB 场景仅传输 27.65MB，进一步减少 **26.8%**。CPU 临时重排压缩，浏览器恢复完全相同的 `.splat`，未新增点数、颜色、坐标或旋转量化；原始 PLY 下载仍保留。旧浏览器及压缩失败可回退原文件。

2026-09-19 对同一真实作品、禁用 HTTP 缓存、固定 8Mbps / 80ms 网络条件的浏览器实测：原文件下载及准备 **43.48 秒**，压缩传输并还原 **30.01 秒**（约减少 31%），其中浏览器解包约 **0.19 秒**；两个结果的 SHA-256 完全一致。这是一次受控网络样本，不含 GPU 推理与工作室解析时间，不代表所有用户都达到相同秒数。没有升级 GPU、增加实例或保温，压缩缓存仅在现有 CPU 容器临时目录，缩容后清除；编码本身占用少量 CPU 时间。

豆包默认使用 Beam Secrets 中站长的 `ARK_API_KEY`。用户也可在修图设置中填写自己的 Key 和模型；自己的 Key 仅保留在页面内存，刷新清空，经 HTTPS 用于当前修图请求，不写入作品、任务状态或前端构建。

修图提供轻柔/适度强度和主体保护提示词。普通修图仍可能出现模型误改，需要检查结果。扩图会把原图实际贴回生成画布中心，外围使用模型生成内容，以避免中心人物被重新绘制；JPEG 编码仍可能带来轻微像素变化。

每个新任务有独立随机 `job_token`，服务器仅保存哈希。状态、修图、重建及文件列表必须携带 `X-Ruhua-Token`；文件下载使用 **24 小时有效的签名链接**，可凭任务 Token 刷新。旧任务没有授权记录时拒绝访问。不要公开任务 Token 或私人作品链接；已获得有效签名链接的人在到期前仍可下载。

浏览器本地缓存、已下载文件和上传到 `public/` 的资源不受云端签名保护。首页示例必须视为公开素材，不能把私人照片放进 `public/`。操作脚本、备份、`.env.local`、`.beam-token`、`.beam-tools/`、虚拟环境及账户凭据不属于静态站点包，也不要手动拷入 `public/` 或 `out/`。

## 首页场景的制作与边界

本版首页素材来自用户提供的参考图，经 ImageGen 扩展画面，再通过真实 SHARP 推理生成 PLY。模型转换使用：

```powershell
node scripts/prepare-landing.cjs artifacts/landing.ply
```

脚本生成 `public/scene/landing.ksplat`、移动设备版本 `landing-lo.ksplat` 和场景清单。需要同时维护对应首页海报，保证加载前后的画面一致。

单张图片只能提供有限视角的信息，SHARP 无法可靠还原被遮挡的背面。首页采用受限的安全观察角度；这不是完整的 360° 重建。更换素材后必须在浏览器实际检查镜头、主体清晰度和移动设备体验。
